# Architecture

This document explains how WatchDocs is organized, how a document travels from the iPhone to the watch, and why some technical choices were made.

## Overview

The core problem: watchOS has no PDFKit, QuickLook or WebKit, so the watch cannot render documents. All conversion therefore happens on the iPhone, and the watch only receives three kinds of content it can display natively:

- **page images** (HEIC, or JPEG as a fallback),
- **plain text** (UTF-8),
- **tables** (JSON, one file per sheet).

A converted document is a **package**: a folder with a `manifest.json` and the files it lists.

## Repository layout

| Folder | Role |
|---|---|
| `Packages/WatchDocsKit` | Shared Swift package for iOS and watchOS: models, transfer protocol, watch storage, platform-independent logic (CSV, text decoding, Word XML). Swift 6 language mode, builds and tests on Linux too. |
| `WatchDocs` | iOS app: import, converters, sending pipeline, SwiftUI screens. |
| `WatchDocsShare` | Share extension: drops shared files into the App Group inbox. |
| `WatchDocsWatch` | watchOS app: background reception, library, Pages / Text / Table readers. |
| `Shared` | Code and String Catalog used by both the iOS app and the extension. |
| `Tests` | Converter unit tests (with fixtures) and XCUITest. |
| `Configs` | Signing settings. Personal values live in `Local.xcconfig`, which is not committed. |

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`, so the project definition stays readable, reviewable text and never causes merge conflicts.

## Data model

```swift
struct DocumentManifest: Codable, Sendable, Identifiable {
    let id: UUID
    var title: String
    let sourceType: SourceType      // pdf, image, photo, word, excel, text
    let createdAt: Date
    let modes: [ReadingMode]        // pages, text, table (preferred first)
    let pageCount: Int
    let totalBytes: Int64
    let files: [PackageFile]        // name, kind, bytes, sha256
    let sheetNames: [String]
    let schemaVersion: Int
}
```

On the watch, a document is the folder `Documents/<uuid>/` containing `manifest.json`, the listed files and a `.complete` marker written once every file is verified.

## Transfer protocol

Transport goes through WatchConnectivity, which queues transfers and delivers them even when the watch app is closed.

1. The iPhone sends `manifest.json` with `transferFile` (`kind = manifest`), then the thumbnail, text, tables and pages in order.
2. The watch moves each received file out of the system inbox **before** `session(_:didReceive:)` returns (the system deletes it afterwards), into `Staging/`.
3. Each file is checked against the manifest (size, then SHA-256) and moved into `Documents/<uuid>/`. A file that arrives before its manifest waits in `Pending/<uuid>/`.
4. When every file is present, the watch writes `.complete` and sends `ack` with `transferUserInfo`. The iPhone marks the document *Delivered* and deletes its local package.
5. `delete` works in both directions. The watch keeps tombstones of deleted documents so late files are discarded.
6. A corrupted file, or a document that stopped progressing (for example the app was killed between reception and storage), triggers a `resend` request listing the missing files.

```swift
protocol DocumentTransport: Sendable {
    func send(_ package: DocumentPackage) async throws
    func resend(_ package: DocumentPackage, names: [String]) async throws
    func delete(documentId: UUID) async throws
    func rename(documentId: UUID, title: String) async throws
    var events: AsyncStream<TransportEvent> { get }
}
```

`WCSession` itself sits behind a smaller `SessionLink` protocol. The real implementation is `WatchConnectivityLink`; tests use `InMemoryLink`, which can reorder, duplicate or drop deliveries.

## Conversion pipeline (iPhone)

- Conversions run **one document at a time** in a detached task, so the UI never blocks and memory does not grow with the queue.
- PDF pages are rendered with Core Graphics into a white bitmap at the chosen width (500, 800 or 1200 px), honoring page rotation, and written to disk **in batches of five**. Page count is therefore unlimited.
- Word and Excel files are laid out by an off-screen `WKWebView` and paginated with `UIPrintPageRenderer` into a narrow A5-like page, which reads better on a small screen. If layout fails, the Text or Table mode is still offered.
- `.xlsx` sheets are read with CoreXLSX, `.docx` text is extracted from `word/document.xml` (ZIPFoundation + `XMLParser`), CSV uses a small RFC 4180 parser that detects `,`, `;` and tab separators.
- Imported files are copied first, so an interrupted conversion can resume at the next launch.

## Share extension

WatchConnectivity is not available in app extensions. The extension copies shared files into an App Group inbox and posts a local notification. The main app converts and sends them as soon as it runs (opened, notification tapped, or background processing task).

## Watch readers

- **Pages**: one page at a time, horizontal swipe, Digital Crown zoom from 1x to 4x, pan when zoomed, double tap to reset. Images are decoded on demand and at most three pages (previous, current, next) stay in memory.
- **Text**: the text is split into paragraphs and laid out lazily, so long documents open fast. Four sizes based on Dynamic Type styles.
- **Table**: two-dimensional scroll view with a pinned header row and a sheet picker.

## Design decisions

- **No page or document limit.** The original requirements capped documents at 200 pages and storage at 500 MB. Both caps were removed; the iPhone only refuses a send that would not fit in the free space reported by the watch, plus an optional user-defined cap.
- **Manifest sent as a file**, not as `userInfo`: with thousands of pages it can exceed a reasonable `userInfo` size. Control messages (`ack`, `delete`, `rename`, `resend`) stay small and use `transferUserInfo`.
- **Five-digit page names** (`page_00001.heic`); sorting uses the parsed number, not lexical order.
- **Disk is the source of truth on the watch** (`manifest.json` + `.complete` marker), instead of SwiftData. This survives restarts and interrupted transfers with less moving parts. SwiftData is used on the iPhone for the document list.
- **Swift language modes**: `WatchDocsKit` uses Swift 6 with strict concurrency as errors. App targets use Swift 5 mode with complete concurrency checking as warnings, to avoid being blocked by SDK annotations that change between Xcode versions.
- **Ticket mode** uses a white background to maximize perceived brightness. watchOS does not let apps force brightness or keep the screen on.

## Dependencies

| Package | Why |
|---|---|
| [ZIPFoundation](https://github.com/weichsel/ZIPFoundation) | Read `word/document.xml` inside `.docx` files (Text mode). |
| [CoreXLSX](https://github.com/CoreOffice/CoreXLSX) | Read `.xlsx` sheets (Table mode). |

SHA-256 uses CryptoKit; a small portable implementation is used only when the package is built on Linux.
